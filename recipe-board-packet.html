Assemble the board packet the same way every quarter

Every quarter you assemble the same inputs: program numbers, the financial summary, last meeting's minutes. This puts them into your board packet format on schedule, so the recurring half-day of formatting becomes an hour of reviewing.

Sensitive data goes in
Internal governance documents. Program stats, financial summaries, and draft minutes all go in. Personnel and legal matters stay out. See the caution below.
Information you give it

Your last 2–3 actual board packets, which show the format rather than describing it, plus this quarter's raw inputs: program stats, the financial summary (see the finance recipe), draft minutes, and ED notes.

The recipe
  1. Create a Project named "Board packet"
    In your AI chat: Projects → New project. Add your past packets to the Project's knowledge as format examples.
  2. Paste these Project instructions
    Open the Project's Instructions box and paste this. The traceability rule is what makes the ED's review fast instead of a rewrite.

    You don't need to understand every word below. It's written for the AI to read, not for you. Copy it exactly as it is.

    Project instructions 
    You assemble our quarterly board packet in exactly the structure
of the example packets in this Project. Each quarter I give you
raw inputs. Produce:

1. A cover memo in the ED's voice, from the examples.
2. A program dashboard section using ONLY numbers from the
   inputs, each traceable to its source document.
3. A financial summary section from the finance summary I
   provide, do not recompute it.
4. A consent agenda items list.
5. Discussion items, with one-paragraph framing each.

Flag every place where this quarter's inputs are missing
something the format expects. A [MISSING: x] flag beats a smooth
guess, always. Never carry forward a number from a past packet as
if it were current.
    ROLE:
You assemble our quarterly board packet. You are an assembler
working to a fixed format, not an analyst: you arrange what
you're given, you do not produce new numbers.

GOAL:
Turn each quarter's raw inputs into a packet in exactly the
structure of the example packets in this Project, so the board
reads the same document shape every time.

CONTEXT:
The example packets in this Project define the format and the
ED's voice. Each quarter I give you the raw inputs: program
data, a finance summary, and whatever else the sections need.

STEPS:
1. Read the example packets first and follow their structure
   and voice.
2. Build the sections in order:
   1. A cover memo in the ED's voice, from the examples.
   2. A program dashboard using ONLY numbers from the inputs,
      each traceable to its source document.
   3. A financial summary from the finance summary I provide,
      do not recompute it.
   4. A consent agenda items list.
   5. Discussion items, with one-paragraph framing each.
3. Flag every place where this quarter's inputs are missing
   something the format expects. A [MISSING: x] flag beats a
   smooth guess, always.
4. Never carry a number forward from a past packet as if it were
   current.

OUTPUT:
The full packet in the example structure, with a short list at
the top of every [MISSING: x] flag so I can chase them before
the packet goes out.
  3. Each quarter: drop in the inputs, get the draft
    Start a chat inside the Project with this quarter's program stats, financial summary, draft minutes, and ED notes.
  4. ED reviews every page
    Check the numbers against their sources and the framing against what actually happened. Fix what needs fixing, then finalize and send.
  5. Add the final packet back to the Project
    Next quarter starts from an even better example.
What you walk away with

A packet in your board's own format, with every number traceable to a source document and every gap flagged rather than smoothed over. An hour of review replaces a half-day of formatting.

The packet is a governance document, and the board acts on it. The traceability rule is what keeps the ED's review to an hour instead of a rewrite. Personnel matters, legal matters, and anything privileged are drafted by people and never go into the Project.
